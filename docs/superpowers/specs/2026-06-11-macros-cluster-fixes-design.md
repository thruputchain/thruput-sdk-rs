# Macros cluster fixes — design

**Date:** 2026-06-11
**Source:** `docs/sdk-review-2026-06-10-remaining.md`, macros cluster (5 findings)
plus the related consumer-experience finding "Examples disagree on #[contract]
storage/Default boilerplate".

## Findings addressed

1. **(medium)** `#[contract_type]` enums get an identity `MintableType` while
   structs recursively mint fields — auth-token children in enum payloads are
   never minted (`crates/macros/src/contract_type.rs:34-47`).
2. `#[contract(storage = false)]` silently discards all state mutations from
   `&mut self` methods (`crates/macros/src/common/exports.rs:316-321`).
3. Bare-impl `#[contract]` silently skips non-`pub` methods, including
   `pub(crate)` (`crates/macros/src/common/contract.rs:226-238`).
4. Four copy-pasted auth-handle walkers in `contract_type.rs`
   (lines 174-297, 467-518).
5. `#[storage]` swallows attribute arguments and emits an unhygienic
   unqualified `#[derive(Storage)]` (`crates/macros/src/lib.rs:119-135`).
6. **(medium, consumer-experience)** Three stateless example contracts use
   three different `storage = false` / `derive(Default)` spellings.

Backward compatibility is not a constraint (sdk_rs is pre-launch).

## 1. Enum MintableType recursion (the bug)

**Problem.** For structs, `#[contract_type]` generates a mirrored `Preimage`
struct (every field type `T` becomes `<T as MintableType>::Preimage`) and a
`mint_into_parent` that recurses field-by-field, so a `Signed<T>` field mints a
child `AuthTokenNode`. For enums it emits `type Preimage = Self` and an
identity `mint_into_parent` that never touches `children`. Meanwhile the
collect/receive walkers generated by the same macro DO recurse into enum
variant fields, so a `Signed<T>` inside an enum variant compiles, publishes a
plausible spec, mints no child node, and fails at consume time with a missing
or sentinel (`u32::MAX`) handle.

**Fix.** Generate for enums exactly what structs get:

- A mirrored preimage enum in a hidden module (`__preimage_Ident::Preimage`),
  with the same variants, the same explicit discriminants, `#[repr(i32)]`, and
  `#[derive(::sdk::ReadXDR, ::sdk::WriteXDR)] #[xdrs(crate = "::sdk::__xdrs")]`.
  Every field type `T` is replaced by `<T as MintableType>::Preimage`.
- `impl MintableType for Ident { type Preimage = __preimage_Ident::Preimage; }`
- `impl Mintable for Ident` whose `mint_into_parent` matches on the preimage
  variant and calls `<T as Mintable>::mint_into_parent(field, children)` for
  each field, reconstructing the corresponding variant of the original enum.

All variant shapes the macro accepts (unit, tuple, named-field) are handled in
a single codegen path. No identity special case for fieldless enums: the
mirror is generated unconditionally so there is one code path. The preimage
enum's wire format intentionally differs from the minted enum's wire format
wherever a `Signed<T>` field appears (preimage carries
`AuthTokenPreimage<T::Preimage>`; the minted value encodes zero bytes with the
data in child nodes) — identical to the existing struct behavior.

## 2. Drop `storage = false` entirely

**Problem.** With `storage = false`, generated entrypoints for `self`-receiver
methods construct a throwaway `<Self as Default>::default()`, invoke the
method, and drop it — mutations to real fields silently vanish. The macro
cannot detect the trap (it sees only the `impl` block, not the struct).

**Why the flag is removable.** The storage path costs nothing for stateless
contracts: `Node<T>` is a plain wrapper (`deref` returns `&T`), storage-struct
fields are keypath-derived handles (no loads or saves happen at construction),
and `derive(Storage)` already supports unit structs
(`From<Keypath> { Self }` — `crates/macros/src/storage.rs:61-75`). So a
stateless contract goes through the normal storage path for free.

**Fix.**

- Delete the `storage` config key, `config.storage()` and its tests, and the
  Default-construct codegen branch (including the `TODO` about asserting
  `Default`). `#[contract]` always generates the storage path:
  `Node<Self>` from `Keypath::root()`.
- Old `#[contract(storage = ...)]` usage fails with darling's unknown-field
  error at the attribute site.
- Migrate the ~20 integration-test contracts and affected example contracts:
  on unit structs with `self`-receiver methods, replace `#[derive(Default)]`
  with `#[storage]`; on associated-fn-only contracts, strip the dead
  `storage = false` and `Default` boilerplate entirely (versioned_caller's
  minimal spelling becomes the canonical one). If any migrated contract turns
  out to have a fieldful non-storage state type that relied on `Default`
  values, convert it to storage handles or associated functions.

**Resulting matrix.** Fieldful storage struct → mutations hit real storage.
Unit struct → nothing to mutate. Fieldful plain struct (the trap) → does not
compile (`From<Keypath>` unsatisfied).

### ContractState diagnostic trait

To make the failure self-explaining, the sdk gains a marker trait and the
generated state-construction code references it instead of bare
`From<Keypath>`:

```rust
#[diagnostic::on_unimplemented(
    message = "`{Self}` cannot be used as contract state",
    note = "methods taking `&self`/`&mut self` require the state type to be a \
            storage struct: add `#[storage]` to `{Self}`",
    note = "contracts with only associated functions (no `self`) don't need it"
)]
pub trait ContractState: From<Keypath> {}
impl<T: From<Keypath>> ContractState for T {}
```

The bound is only emitted for `self`-receiver entrypoints, so the diagnostic
fires exactly when `#[storage]` is mandatory and missing — never for
associated-fn-only contracts. Caveat to verify at implementation time: the
workspace MSRV must be ≥ 1.78 for `#[diagnostic::on_unimplemented]`; if it is
lower, omit the attribute (the marker trait is harmless and the error stays a
plain trait-bound message).

## 3. Visibility rule for bare-impl methods

**Problem.** Bare-impl `#[contract]` exports only `Visibility::Public`
methods; a `pub(crate)` or private method is silently omitted from exports,
client, spec, and mock registry. Trait impls export everything regardless.

**Fix.** In bare impl blocks:

- `pub` → exported (unchanged).
- private (no visibility keyword) → skipped; this remains the deliberate way
  to write helper methods inside the impl block.
- `pub(crate)`, `pub(super)`, `pub(in ...)` → spanned compile error:
  "ambiguous visibility for contract method: use `pub` to export it or make
  it private to keep it internal". Covered by a trybuild compile-fail test.

Trait impls keep exporting all methods, unchanged. The rule gets documented in
`#[contract]`'s rustdoc.

## 4. Auth-handle walker dedup

Collapse the four near-identical generators
(`expand_collect_auth_handles_struct`, `expand_receive_auth_handles_struct`,
`expand_collect_auth_handles_enum`, `expand_receive_auth_handles_enum`) into a
single parameterized generator (parameters: trait path, method name, extra
argument tokens), preserving the generated output token-for-token where
practical. Pure refactor with no intended behavior change, asserted by the
existing test suite plus the new enum-mint tests.

## 5. `#[storage]` hygiene

- Reject attribute arguments: `#[storage(anything)]` becomes a spanned error
  ("#[storage] takes no arguments") instead of silently compiling with the
  arguments dropped. Covered by a trybuild compile-fail test.
- Emit `#[derive(::sdk::Storage)]` (path-qualified) so the derive resolves
  without a user import.
- Fix the same hygiene issue inside `derive(Storage)`'s generated block:
  `use sdk::storage::*` becomes `::sdk::storage::*` (or fully qualified
  paths), matching the rest of the macro crate.

## Testing

- **Enum minting:** sdk-side tests (extending the patterns in
  `crates/sdk/src/mintable.rs` tests and `crates/sdk/tests/signer_lifecycle.rs`)
  that mint a `Signed<EnumWithSignedField>` and assert the child
  `AuthTokenNode` is produced, plus a round-trip through the receive path
  binding the inner handle; a fieldless-enum case asserting no children and a
  stable wire encoding.
- **Visibility:** trybuild compile-fail test for `pub(crate)` in a bare impl;
  compile-pass coverage that private helpers are still allowed and skipped.
- **`#[storage]` args:** trybuild compile-fail test.
- **Storage-flag removal:** the migrated integration-test and example
  contracts compiling and their existing tests passing is the verification;
  plus a trybuild compile-fail test that a fieldful plain struct with
  `&mut self` methods produces the `ContractState` diagnostic.
- Existing macro snapshot/trybuild suites must pass after the walker dedup.

## Documentation

- `#[contract]` rustdoc (currently none): state-type requirement
  (`From<Keypath>` via `#[storage]`, optional only for associated-fn-only
  contracts), the bare-impl visibility rule, and removal of the `storage`
  flag.
- `#[contract_type]` rustdoc: enum variants mint recursively; `Signed` fields
  in variants become child tokens.
- `#[storage]` rustdoc: takes no arguments; works on unit and named structs.
